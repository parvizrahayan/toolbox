# دستورکار: اتصال دامنه سفارشی به GitHub Pages

از این چک‌لیست برای هر پروژه‌ی جدید که قراره روی یه دامنه‌ی سفارشی (مثل `example.ir`) بره، استفاده کن.
جاهایی که `[DOMAIN]`, `[ORG_OR_USER]`, `[REPO]` نوشته شده رو با مقادیر واقعی پروژه جایگزین کن.

---

## پیش‌نیاز
- دامنه رو بشناس: ثبت‌کننده (رجیسترار) کجاست، و DNS واقعیش کجا مدیریت می‌شه (اگه نیم‌سرورها روی Cloudflare اشاره کردن، DNS رو باید تو Cloudflare بزنی نه تو پنل رجیسترار).
- بدون که ریپو زیر اکانت شخصیه یا زیر یه Organization — این مسیر تایید دامنه رو عوض می‌کنه.

---

## مرحله ۱ — فایل CNAME تو ریپو
```
cd /o/dev/[REPO]
```
```
echo -n "[DOMAIN]" > CNAME
```
```
git add CNAME
```
```
git commit -m "fix: set CNAME to [DOMAIN]"
```
```
git push
```
⚠️ محتوای فایل باید فقط و فقط خود دامنه باشه — بدون `https://`, بدون `www`, بدون اسلش انتهایی.

---

## مرحله ۲ — تلاش اول برای ثبت دامنه روی Pages
```
gh api -X PUT repos/[ORG_OR_USER]/[REPO]/pages -f cname=[DOMAIN]
```

**اگه خطای "Invalid cname / already taken" یا "must verify your domain" گرفتی** → برو مرحله‌ی ۳ (تایید مالکیت دامنه). این خیلی محتمله، پس معمولاً باید این مرحله رو انجام بدی.

---

## مرحله ۳ — تایید مالکیت دامنه (Domain Verification)
آدرس درست بستگی داره ریپو مال اکانت شخصیه یا Organization:

- اکانت شخصی:
```
https://github.com/settings/pages
```
- Organization:
```
https://github.com/organizations/[ORG]/settings/pages
```

اونجا **Add a domain** رو بزن، `[DOMAIN]` رو وارد کن. گیت‌هاب یه رکورد TXT می‌ده شبیه:
```
Name:  _github-pages-challenge-[ORG_OR_USER]
Value: <یه رشته‌ی طولانی>
```

### اضافه کردن این رکورد تو Cloudflare
1. وارد `dash.cloudflare.com` شو → دامنه رو انتخاب کن → **DNS > Records**
2. **Add record**
3. Type: `TXT`
4. Name: فقط `_github-pages-challenge-[ORG_OR_USER]` (بدون `@`، بدون خود دامنه — کلادفلر خودش اضافه می‌کنه)
5. Content: مقداری که گیت‌هاب داد
6. Save

چند دقیقه صبر کن، برگرد تو صفحه‌ی گیت‌هاب و **Verify** رو بزن.

> نکته: اگه ریپو هم زیر اکانت شخصیته هم قراره Organization دخیل باشه، ممکنه لازم باشه این تایید رو **جدا برای هر دو** (هم شخصی هم Organization) انجام بدی.

---

## مرحله ۴ — رکوردهای A برای خود گیت‌هاب پیجز
تو همون بخش DNS کلادفلر، ۴ رکورد A بساز (هر بار یکی، همه با Name = `@`):
```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```
روی هر ۴ تا، **Proxy status** رو خاموش کن (بذار رو **DNS only** / ابر خاکستری). اگه پروکسی کلادفلر روشن بمونه، گیت‌هاب نمی‌تونه گواهی SSL صادر کنه.

---

## مرحله ۵ — دوباره ثبت CNAME روی Pages
```
gh api -X PUT repos/[ORG_OR_USER]/[REPO]/pages -f cname=[DOMAIN]
```
این بار نباید خطا بده.

---

## مرحله ۶ — چک وضعیت
```
gh api repos/[ORG_OR_USER]/[REPO]/pages
```
دنبال این مقادیر بگرد:
- `"cname": "[DOMAIN]"`
- `"protected_domain_state": "verified"`
- `"https_certificate": { "state": "approved" }` ← اگه هنوز `"state": "new"` یا `"errored"` بود، چند دقیقه تا چند ساعت صبر کن و دوباره چک کن.

---

## مرحله ۷ — فعال کردن Enforce HTTPS
فقط وقتی گواهی approved شد:
```
gh api -X PUT repos/[ORG_OR_USER]/[REPO]/pages -F https_enforced=true
```

---

## مرحله ۸ — تست نهایی
دامنه رو تو مرورگر (ترجیحاً Incognito) باز کن و مطمئن شو:
- قفل سبز/امن نشون می‌ده
- سایت درست همون پروژه‌ست (نه یه ریپوی دیگه که قبلاً همین دامنه رو داشته)

---

## خطاهای رایج و راه‌حل سریع

| خطا | دلیل | راه‌حل |
|---|---|---|
| `Certificate not valid for domain name` (تو SSL Labs) | CNAME یا رکورد A هنوز درست نیست، یا گواهی صادر نشده | مرحله ۱، ۳، ۴ رو چک کن |
| `Invalid cname ... already taken` | یه ریپوی دیگه (حتی زیر یه Org دیگه) این دامنه رو قبلاً گرفته | تو داشبورد پروژه‌ها/ریپوها بگرد ببین کدوم ریپو صاحب واقعیشه؛ اول از اونجا حذفش کن |
| `must verify your domain` | تایید مالکیت (مرحله ۳) هنوز انجام نشده | مرحله ۳ رو کامل کن |
| `The certificate does not exist yet` موقع enforce https | گواهی هنوز صادر نشده | صبر کن، دوباره مرحله ۶ رو چک کن |
| هشدار "Visitors cannot reach www.[DOMAIN]" تو Cloudflare | چون رکورد جدا برای `www` نساختی | اگه از www استفاده نمی‌کنی، بی‌خیالش شو |
